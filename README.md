# Research Contribution Architect

给 Codex 使用的科研贡献挖掘 Skill。适用于已经复现 baseline、分析失败案例，并在真实代码里实现改进、获得性能提升，却还缺少明确创新点和论文叙事的阶段。

## 最重要的原则

**从已实现、已有涨点的同一个方法中挖掘科研创新，而不是另起炉灶设计未来算法。**

Skill 会深入理解现有工程改动，从具体实现中提炼作用机制、统一科学问题和有意义的理论联系，并将它们组织为一条有吸引力的论文主线及 2～3 个相互支持的贡献。若实际只能支撑一到两项贡献，不强行凑数。

三套方案 A/B/C 代表**同一冻结实现的三种学术定位和论文叙事**，不是三套新算法。不允许通过尚未实现的状态估计器、更新机制或新目标函数获得“新颖性认可”。所有性能数字来自当前已跑出的真实实验，不将整体涨点拆解成未消融组件的独立收益。

## 研究团队

| 角色 | 主要工作 |
|---|---|
| 主 Codex | 私下理解代码和实验，核对实现边界，整合方案并写报告 |
| Astra 1 | 针对已有成果形成 A/B 两套学术抽象与贡献组织 |
| Astra 2 | 独立探索较大胆、但仍由同一实际实现支撑的方案 C |
| Astra 3 | 独立检索文献，检查真实新颖性与学术定位 |
| Astra 4 | 独立评价论文中心性、贡献体系和可读性 |

**创新者与审稿人隔离。** 审稿人只能看到精简冻结的匿名评审包，不能阅读项目源码、原始实验日志、调试对话或创作者讨论，也不能看到彼此的意见。仅开启不同线程不一定足以形成文件权限隔离；若本地运行环境无法做到，必须如实说明。

当审稿人认为新颖性不充分时，创新团队**只能继续挖掘现有已实现机制的高层次学术价值**，重新组织科学问题、贡献和最近邻差异；不得添加没实现的算法来拿高分，也不得编造原创性。

## 安装

将仓库克隆到项目的 Skills 目录，使 `SKILL.md` 位于文件夹根部：

```bash
mkdir -p .agents/skills
git clone https://github.com/WinstonJQ/research-contribution-architect.git .agents/skills/research-contribution-architect
```

在 Codex 中调用：

```text
请使用 $research-contribution-architect，对当前 baseline 的真实涨点版本进行科研创新挖掘。只分析现有已经实现并运行的改进，不要提出未实现的新算法作为论文贡献。

请从实际失败和改进机制中提炼统一科学问题，并形成三套对同一实现的学术叙事，经两位独立 Astra 审稿后，选出最能继承现有成果、具有准确学术抽象和清晰贡献点的方案。

只交付一份易读的 Markdown，不要附录、审计日志或未来算法设计。
```

若之前安装了旧版本，建议在该 Skill 目录执行 `git pull origin main`，或删除原文件夹后重新克隆。

## 唯一输出

`research_synthesis/research_contribution_report.md`

报告包含：值得研究的科学问题、三套基于真实实现的科研叙事、审稿增强摘要、最终推荐科研方法、可直接用于论文的故事与 Contributions。

不输出实验审计文档、评审原始记录和附录；但任何学术创新主张仍须忠于真实实现及已有证据。模型评审不等于正式论文审稿或新颖性保证。

完整规则见 [SKILL.md](SKILL.md)。
