# Research Contribution Architect

一个为 Codex 设计的科研创新 Skill。适用于已经复现 baseline、分析过失败案例、并获得真实性能改善，但尚未形成清晰创新点及论文主线的阶段。

## 核心目标

从小型工程改进提炼出有解释力的科研思想，并在必要时进一步重构算法，形成具有统一科学问题、2～3 个相互支撑的技术贡献和清楚新颖性差异的论文方案。

它不是代码审计报告生成器，也不只是论文润色工具。

## 研究团队

| 角色 | 职责 |
|---|---|
| 主 Codex | 理解项目、协调创新和评审、整合并撰写最终方案 |
| Astra 1 创新架构师 | 提出围绕共同科学问题的方案 A/B |
| Astra 2 突破研究员 | 独立构思潜在突破方案 C |
| Astra 3 独立新颖性审稿人 | 检索最近邻文献，检验技术差异并提出具体增强建议 |
| Astra 4 独立方法与叙事审稿人 | 判断算法实质、贡献体系和可读性 |

两位审稿人只看匿名冻结的精简评审包，不接触原始实验日志、源码、创作者讨论或彼此意见。若运行环境不能在权限上实施隔离，必须如实说明，不能假装严格盲审。模型是否真正由 Astra 执行也需依实际工具返回判断。

## 工作流程

1. 主 Codex 了解已实现机制和失败案例，内部核对必要事实。
2. 两位创新者分头探索，形成 A/B/C 三套实质不同的研究方案。
3. 主 Codex 构造去除原始项目上下文的精简评审包。
4. 两位独立审稿人分别评估新颖性、算法和叙事，并提出具体增强方案。
5. 对不达标方案进行实质修改、重新冻结并复评。不得只改名词，也不得为追求通过而虚构成果。
6. 最终只生成一份易读的科研方案报告，不包含日志和审计附录。

## 使用方式

将仓库克隆至 Codex 可发现的 Skills 目录，确保 `SKILL.md` 位于一个名为 `research-contribution-architect` 的文件夹内。

项目级安装示例：

```bash
mkdir -p .agents/skills
git clone https://github.com/WinstonJQ/research-contribution-architect.git .agents/skills/research-contribution-architect
```

随后在项目中的 Codex 会话调用：

```text
请使用 $research-contribution-architect，对当前已取得涨点的 baseline 工作进行科研创新挖掘。请按照 Skill 规定的团队分工和严格评审隔离，形成三套候选方案并迭代增强，最后只输出一份可读的研究报告。本轮不修改算法代码。
```

## 唯一产出

`research_synthesis/research_contribution_report.md`

报告由五个部分组成：核心科学问题、三套创新方案、独立评审带来的实质增强、最终推荐方法、可用于论文的故事与贡献。

**重要：** Skill 的目的是提高科研构思质量；内部模型评审不能替代对真实文献的完整检索或实验验证。若未实际运行隔离评审、尚未获得认可或关键机制未实现，报告必须准确说明状态。

更多具体工作规则见 [SKILL.md](SKILL.md)。
