# 单文档研究报告模板

本模板仅规定最终唯一文件 `research_synthesis/research_contribution_report.md` 的组织方式。**不要拆分为多个文件，也不要单独产出候选或评审文档。**

所有二级标题都要填写可核实内容；证据不足时明确写未知和最小补证方式。不需要为填满篇幅而写空话。表格可在信息密集时使用，正文尽量简洁准确。

# 从工程涨点到核心算法贡献：研究方案评估

元信息：日期｜仓库/版本/commit｜数据及评估口径｜证据覆盖程度｜评审执行状态

## 1. 结论速览

- **最值得研究的一个科学问题**：一两句话。
- **目前得到证实的进展**：准确数值、对照、证据位置；缺失则标未知。
- **三套方案的本质差别**：各一句话，不能只有名称差别。
- **当前首选**：A/B/C/条件性推荐/证据不足不选，并解释一句理由。
- **距离真正算法创新还差什么**：一个最关键的主流程改变。
- **下一步最有判别力的实验**：一个实验及其失败标准。

## 3. 核心科学问题与四层学术抽象

**科学问题**：在何种条件下，什么静态假设或决策机制导致什么可测损失？

| 工程改动 | L1 真实代码行为 | L2 可能有效的机制 | L3 可迁移的方法原则与理论边界 | L4 能主张的研究贡献和证据 |
|---|---|---|---|---|
| | | | | |

**共性机制**：哪些改动能由同一原理解释？哪些只是配套的工程优化，不能硬升格？

**竞争解释**：至少两种有区别的解释与其鉴别实验。

## 5. 两位 GPT Astra 独立评审与分歧分析

**评审运行记录**：是否实际启动两个独立线程；实际模型/角色（若能核实）；是否各自读取冻结版；是否相互隔离；时间/返回状态。

### 评审 A：科学性与创新性

报告 A/B/C 六维 1–5 分（科学问题价值、证据和机制、算法核心差异、与已有工作区别、清晰度、可验证性）；逐案说明得分依据、致命问题、排序、首选条件、最关键反证实验。

### 评审 B：算法与论文说服力

使用相同六维评分；逐案说明得分依据、致命问题、排序、首选条件、最关键反证实验。不可根据评审 A 的结果修改评审 B 的原始判断。

### 两份评审的共识、分歧与原因

- 一致认可和一致反对什么；
- 分歧在哪里，是科学假设、实现可行性还是证据缺口造成；
- 不能简单对评分取平均；
- 哪个实验能真正化解分歧。

**如果无法真实启动两个 Astra**：这一节清楚写“独立 Astra 评审未执行”及原因。若仅有一个真实结果，只记录一个，不虚构第二份。附两个可供手动运行的独立评审指令，明确须同时提供冻结的 A/B/C 和相同证据包；不得写伪造的双评审共识。

## 6. 综合结论：主选论文主线与核心算法重构

- **主选 A/B/C**，选它的实证、方法与可读性理由。
- **备选方案**及触发切换的实验条件。
- **不能随意拼接**：若吸收别案组件，新增假设和未评审之处必须标明。

### 两段无需术语的论文故事

第一段：baseline 在哪种情况下发生了什么可观察失败，为什么现有关键决策不适用。

第二段：我们改变算法的哪一个动作、如何通过可测机制解决上述失败、什么证据已有或待验证。

## 7. 最小验证路线与审稿风险

按优先级列出 **最多 3 个** 最有判别力的实验。每个实验包含：机制预测、竞争解释的预测、控制变量、成本、失败标准。优先选择能区分三方案或决定是否推进主选方案的实验。

列出与方法最相近的研究（核实来源/待查清单），以及三条最强的审稿质疑与对应证据。

最后执行三个检查：30 秒理解测试、去自造术语测试、单图展示测试。若任何一项不通过，标明仍需修订的问题。
