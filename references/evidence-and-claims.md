# 证据与主张协议

本文件是执行证据审计、文献归属及机制验证的工作说明。读完后先取证，再抽象。

## A. 优先检查什么

1. 项目任务定义、输入输出、评价目标与实际使用场景。
2. baseline 原论文/官方实现与仓库中的复现版。如果无法访问原论文，不要假定完全忠实于官方配置。
3. 当前最优版本相对复现 baseline 的 git 变更，关键训练/推理入口、配置、日志与实验跟踪表。
4. 失败案例是如何挑选出来的：随机抽样、全量统计还是事后挑选；不同类型的发生频率与效果分解。
5. 评价可靠性：固定测试集使用频次、开发/测试集边界、随机种子、方差、样本量、显著性（仅在适用时）；统一推理预算和其他资源。
6. 与方法本身无关的潜在增益来源：数据清洗、额外算力、超参数调优、模型大小、检索数据变化、评估脚本变动、样本泄漏。

## B. 证据分类

给每个重要主张标注以下之一：

- **F（实现事实）**：源码、配置、提交记录可定位；只说明做了什么。
- **O（观测结果）**：日志/指标/案例可定位；说明发生了什么；若不可比要附限制。
- **H（机制假说）**：合理解释现象，但没有鉴别性证据。
- **T（理论联系）**：与一个理论相似或可用其分析；不等于完成理论推导或定理证明。
- **V（已验证机制）**：有足以区分主要竞争解释的对照或消融支持；仍应说明适用范围。
- **U（尚未核实）**：依赖记忆、口头说法或缺失证据。

**每个科学主张允许结合多个标签，但不能用 F/O 直接推出 V，也不能用 T 直接推出理论创新。**

## C. 失败分析记录单位

每类失败至少记录：

| 字段 | 含义 |
|---|---|
| 失败 ID | 可复查的案例或分组 |
| 触发条件 | 输入或系统状态中的可观测条件 |
| baseline 行为 | 做错了什么；可用具体样例 |
| 当前版行为 | 改善/恶化/不变，以及数量 |
| 候选根因 | 机制解释，不是重复描述症状 |
| 替代解释 | 至少一个其他可能原因 |
| 最小反证 | 什么观察会迫使我们修正解释 |

一个来源于修复成功的单例不够证明普遍机制。优先汇总所有相关样本的分布变化，并展示反例。

## D. 相关研究与理论借用

- 相关方向用于**组织和检验想法**，而不是给工程修补贴高端标签。
- 每提到一个理论，必须说明：它的哪条假设或原则与算法的哪部分对应；哪些地方不对应；最需要补的证据是什么。
- 不具有可验证的概率估计时，不可自动叫“置信度校准”或“贝叶斯不确定性”；任意权重不自动是“鲁棒优化”；分组采样不自动是“课程学习”。
- 文献状态分“已读并核对 / 只看到题录或摘要 / 待查”。文献没有 DOI/arXiv/出版社等可追溯信息时不要伪造。
- 面对邻近研究，重点比较**被研究的失败机制、关键假设、目标函数、信息流、决策时机和资源预算**，而不仅比较模块名。

## E. 关键实验的判别逻辑

每个实验先写：

1. **核心机制预测**：若叙事为真，应该改善哪些失败组，在哪些条件下更明显。
2. **竞争解释预测**：若只是算力增加、筛选有利样本或调参，预期会看到什么。
3. **控制变量**：数据划分、预算、阈值选取、模型、种子、实现版本保持什么一致。
4. **失败标准**：结果如何才算推翻这个机制，或必须降低论述强度。

优先做最便宜且最能区分假说的对照。不鼓励为制造正结果无穷试验；不要为了主张而删除负结果。

## F. 科研贡献的证据门槛

| 贡献声称 | 至少需要 |
|---|---|
| 某失败机制真实存在 | 分组案例或统计与反例分析 |
| 某模块带来增益 | 适当消融或独立对照 |
| 某共同原则解释多个改动 | 统一的机制预测及有区分力的验证 |
| 某算法优于基线 | 同口径可复现的结果；最好含方差、成本 |
| 具有新颖性 | 可靠的最近邻研究比较，不是自封首次 |
| 有数学/理论保证 | 完整前提与可检查的推导或引用；不得以公式装饰 |

当证据不足时使用“可能、推测、待检验”，并写出下一步如何验证，不要绕过证据门槛。
